# PC Logger — локализация

Дата: 2026-09-12
Статус: утверждён
Issue: [#3](https://github.com/navoznov/pc-logger/issues/3)

## 1. Задача

Интерфейс целиком написан по-русски: подписи и тултипы отчёта, пункты меню в
трее, форматы длительностей и названий дней недели. Нужен английский язык — и
нужно, чтобы добавление третьего языка не требовало переделки механизма.

Локализуются три поверхности: HTML-отчёт (~115 строк), трей вместе с
сообщением об ошибке запуска (7 строк) и форматы в `render.js`. Дополнительно
появляется `README.en.md`.

Не локализуются: `docs/known-limitations.md` и документы в
`docs/superpowers/` — они адресованы разработчику, а не пользователю.

## 2. Продуктовые решения

### 2.1 Язык переключается в самом отчёте

Отчёт вшивает все словари и получает `<select>` в шапке; выбор запоминается в
`localStorage`. Отвергнут вариант с ключом `"language"` в `config.json`: он
фиксирует язык в момент генерации, а отчёт — это файл, который открывают
глазами, и менять его язык логичнее там же, где меняют тему.

Цена решения невелика: статическая разметка заполняется одним проходом по
`data-i18n`, а всё остальное и так перерисовывается при смене дня.

### 2.2 Язык по умолчанию — язык Windows, вшитый при генерации

`ReportBuilder` кладёт в payload `lang`, вычисленный из
`CultureInfo.CurrentUICulture`. Пока в `localStorage` пусто, отчёт открывается
на этом языке — том же, на котором говорит трей. Один механизм определения
языка на всё приложение; трей и отчёт не могут разойтись.

Отвергнут `navigator.language`: он развёл бы трей и отчёт на одной машине.

### 2.3 Словари отчёта — обычный dashboard-скрипт

`dashboard/i18n.js` живёт рядом с `render.js`, `regime.js` и `selection.js`.
Существующая инфраструктура покрывает его целиком и без единой правки:

- `csproj` копирует `dashboard\**\*` рядом с exe и вшивает те же файлы в
  сборку — словарь получает и редактируемую копию, и несносимую;
- `ReportBuilder.Render` инлайнит любой `<script src="...">` — отчёт остаётся
  одним файлом;
- `node --test` уже читает эти файлы напрямую — словарь тестируется как код.

Отвергнуты два варианта. Общий `lang/*.json` на оба слоя даёт «один файл на
язык», но требует нового загрузчика в C#, правки `LogicalName` под подпапку и
второго плейсхолдера в `ReportBuilder` с его валидацией. `.resx` с
сателлитными сборками ради семи строк добавляет в релизный zip папки `ru/` и
`en/` с `.dll`.

Следствие, принятое осознанно: новый язык — правка **двух** файлов,
`i18n.js` и `Strings.cs`. Множества строк не пересекаются, поэтому
дублирования нет; есть две точки регистрации вместо одной.

### 2.4 Ключи семантические

`legend.over`, `kpi.median.tip`, `track.power.name` — а не английский текст в
роли ключа. Половина строк отчёта это тултипы на два предложения: как ключи
они нечитаемы и ломаются от любой редакторской правки. Семантический ключ ещё
и не делает ни один из языков привилегированным.

## 3. Архитектура

### 3.1 `src/PcLogger.Core/dashboard/i18n.js`

```js
(function (root) {
  'use strict';
  const DICTS = {
    ru: { $name: 'Русский', 'track.power.name': 'ПК включён', ... },
    en: { $name: 'English', 'track.power.name': 'PC on',      ... }
  };
  let current = 'en';
  function set(lang) { current = DICTS[lang] ? lang : 'en'; }
  function lang()  { return current; }
  function langs() { return Object.keys(DICTS); }
  function t(key, params) { /* см. ниже */ }
  root.I18n = { set, lang, langs, t, DICTS };
})(typeof module !== 'undefined' && module.exports ? module.exports : window);
```

`t(key, params)` ищет по цепочке: `DICTS[current][key]` → `DICTS.en[key]` →
сам `key`. Затем подставляет `{name}` из `params`. Ключ, доехавший до экрана,
— это видимый баг, а не тихая дыра в переводе.

Ключ `$name` — подпись языка в переключателе, на самом этом языке.

### 3.2 Статическая разметка

Шапка, слайдеры, легенда, имена дорожек, шапка таблицы и подсказка панели
выделения не перерисовываются при `redraw()`. Они размечаются атрибутами:

```html
<button id="prev" data-i18n-title="nav.prevDay" data-i18n-aria="nav.prevDay">←</button>
<div class="track-name" data-i18n="track.power.name"
                        data-i18n-title="track.power.tip"></div>
```

`applyStatic()` проходит по `[data-i18n]`, `[data-i18n-title]` и
`[data-i18n-aria]` и заполняет `textContent`, `title` и `aria-label`.
Вызывается при старте и при смене языка.

Разметка остаётся читаемым HTML, а не строкой внутри скрипта: правки вёрстки
и правки текста дают раздельные диффы.

### 3.3 Динамический текст

Конкатенации вида `'нарушений: ' + d.violations` заменяются на
`I18n.t('week.bar.tip', { day: ..., dur: ..., violations: ... })`. Строки, где
важен порядок слов — панель выделения, тултип столбика недели, баннер о сбое
записи, — держатся в словаре целиком, иначе они непереводимы в принципе.

Ключи в исходниках всегда остаются строковыми литералами. Там, где текст
сейчас выбирается по идентификатору — `TRACK_NAMES[zoneId]`,
`NOTHING_AT[zoneId]` — таблица хранит не текст, а готовый ключ
(`{ tPower: 'track.power.name', ... }`), и в `t()` уходит литерал из неё.
Конкатенации вида `t('track.' + zoneId + '.name')` запрещены: они делают
проверку связности ключей (§5.1) слепой ровно там, где она нужнее всего.

### 3.4 Форматы в `render.js`

`render.js` остаётся модулем, пригодным для node-тестов, поэтому зависимость
инъектируется явно, а не берётся из глобали:

```js
Render.use(I18n);   // в шаблоне — рядом с остальной инициализацией; в тестах — в setup
```

- `fmtDuration` берёт суффиксы из `fmt.h` и `fmt.m`: `2 ч 35 м` против `2h 35m`.
- `weekday` переходит на `Intl.DateTimeFormat(lang, { weekday: 'short', timeZone: 'UTC' })`,
  массив `WEEKDAYS` удаляется. Новый язык получает названия дней бесплатно.
- `clock` не меняется. `HH:MM` одинаков во всех целевых языках, а
  `toLocaleTimeString` сломал бы действующий контракт: время строится сдвигом
  эпохи и чтением UTC-полей, чтобы отчёт читался на машине с другой зоной.

### 3.5 `src/PcLogger.Core/Localization/Strings.cs`

```cs
public static class Strings
{
    private static readonly Dictionary<string, Dictionary<string, string>> All = ...;
    public static string Current { get; }                     // Resolve(CultureInfo.CurrentUICulture)
    public static string Resolve(CultureInfo culture);        // двухбуквенный код или "en"
    public static string Get(string key);
}
```

Класс лежит в **Core, а не в App**: на macOS WinForms-слой можно только
скомпилировать, но не выполнить, поэтому вся тестируемая логика обязана быть
по эту сторону границы проектов. `TrayApp` и `Program` только читают строки.

`ReportBuilder.BuildJson` добавляет в payload `lang = Strings.Current`.

### 3.6 Переключатель

`<select id="lang">` в шапке, слева от кнопки «Тема»; опции строятся из
`I18n.langs()` с подписями `$name`. Начальное значение:

```js
I18n.set(localStorage.getItem('pclogger.lang') || DATA.lang);
```

По выбору: запись в `localStorage` → `I18n.set` → `applyStatic()` →
`applyMode(weekShown())` → `redraw()` → `document.documentElement.lang`.

`localStorage` в проекте до сих пор не использовался — `pclogger.lang` первый
ключ. Тема остаётся непостоянной: её поведение задача не затрагивает.

## 4. Границы объёма

Сознательно не делается:

- **Десятичный разделитель.** `ratio.toFixed(1)` печатает `1.5 : 1` на обоих
  языках. Локализация разделителя изменила бы существующий русский вывод.
- **Формат даты.** Подпись дня строится как `MM-DD` срезом ISO-строки и
  остаётся такой.
- **Множественные числа.** Ни одна строка не требует согласования с числом:
  счётчики везде оформлены как «подпись: значение». Если такая строка
  появится, правило добавляется тогда же.

## 5. Тестирование

### 5.1 JS — `tests/dashboard/i18n.test.js`

1. **Паритет ключей.** Наборы ключей `ru` и `en` совпадают ровно. Главный
   страж: забытый перевод падает тестом, а не всплывает в интерфейсе.
2. **Связность ключей.** Каждый ключ из `data-i18n*` шаблона и из вызовов
   `I18n.t('...')` в шаблоне и в dashboard-скриптах существует в словаре;
   мёртвых ключей в словаре нет. Служебные ключи с префиксом `$` (`$name`)
   из проверки на мёртвые исключены: их читает переключатель, а не `t()`.
3. **`t()`.** Подстановка `{param}`, фолбэк на `en`, фолбэк на сам ключ.
4. **Нет кириллицы вне `i18n.js`** — по `dashboard.template.html`,
   `render.js`, `regime.js` и `selection.js`.

Пункт 4 имеет цену: восемь комментариев цитируют русский текст интерфейса
(`«Неделя»`, `превышение`, `«Всего за ПК»`, `"За ПК 23 %"`). От этой правки они
устаревают в любом случае, поэтому переписываются на английский. Без стража
хардкод вернётся при первой же правке разметки.

### 5.2 JS — `tests/dashboard/render.test.js`

Восемь существующих ассертов получают `Render.use(I18n); I18n.set('ru')` и
сохраняют текущие ожидания. К ним добавляются зеркальные для `en`.

### 5.3 C# — `tests/PcLogger.Core.Tests/StringsTests.cs`

1. Паритет ключей `ru` и `en`.
2. `Resolve`: `ru-RU` → `ru`, `en-US` → `en`, `de-DE` → `en`,
   `InvariantCulture` → `en`.
3. Английский тултип трея укладывается в 63 символа после форматирования —
   иначе `NotifyIcon.Text` обрежется на полуслове (`TrayApp.Truncate`).

`ReportBuilderTests` дополняется проверкой, что payload содержит `lang`.

## 8. Что даёт добавление нового языка

Добавить немецкий = добавить ключ `de` в `DICTS` и запись `["de"]` в
`Strings.All`. Переключатель подхватит язык сам через `I18n.langs()`, названия
дней придут из `Intl`, а тест паритета ключей немедленно покажет каждую
строку, которую забыли перевести.
